## Behavior Specs (Angular Base Components — retroactive for 4.1-4.4)

### Requirement: Angular fe-* Component Rendering
The system SHALL render fe-* custom elements in Angular templates using `CUSTOM_ELEMENTS_SCHEMA` and property binding.

#### Scenario: fe-button renders with property binding
- GIVEN an Angular component template
- WHEN the template contains `<fe-button [size]="'xs'" [disabled]="true">`
- THEN the fe-button renders with `size="xs"` and `disabled=true`
- AND no bare attributes are used

#### Scenario: fe-button fails with bare attributes
- GIVEN an Angular component template
- WHEN the template contains `<fe-button size="xs">` (bare attribute)
- THEN the property is NOT set (hybrids `getAttribute` runs after constructor)
- AND the component renders with default values

### Requirement: Angular Zoneless Change Detection
The system SHALL operate without zone.js using `provideZonelessChangeDetection()`.

#### Scenario: Signal state updates render correctly
- GIVEN an Angular component with OnPush change detection
- WHEN a signal value changes
- THEN the view updates without zone.js intervention
- AND no NG0203 errors appear

#### Scenario: Async data fetch updates view
- GIVEN a component fetching data via `effect()`
- WHEN the fetch completes and signal updates
- THEN the template re-renders with new data
- AND change detection runs once (no extra cycles)

### Requirement: Angular Theme Integration
The system SHALL apply WA themes via CSS import order (base → theme → tokens).

#### Scenario: Theme class activates styling
- GIVEN `index.html` with theme class on `<html>`
- WHEN the app loads
- THEN WA components receive correct theme styling
- AND token overrides from `tokens.css` take precedence

#### Scenario: Missing theme degrades gracefully
- GIVEN no theme CSS imported
- WHEN the app loads
- THEN WA components render with base styles only
- AND no CSS custom property errors appear

### Requirement: Angular Factory Pattern
The system SHALL provide `createWhiteLabelApp()` factory returning `Promise<{ root, config }>`.

#### Scenario: Factory bootstraps with defaults
- GIVEN no tenant overrides
- WHEN `createWhiteLabelApp({})` is called
- THEN the app renders with default routes, metaMap, and components
- AND bootstrap uses Angular's `bootstrapApplication()`

#### Scenario: Factory merges tenant routes
- GIVEN tenant provides `extendRoutes: [extraRoute]`
- WHEN `createWhiteLabelApp({ extendRoutes })` is called
- THEN the final routes include both default and extra routes
- AND tenant routes take precedence on path collision

## Delta (for 4.5 — Pages Port)

### ADDED Requirements

#### Requirement: Angular ProductsPage Rendering
The system SHALL render products using `fe-async-content` and `fe-loader` for async data fetching.

##### Scenario: Products load successfully
- GIVEN the Angular app navigates to `/`
- WHEN `ProductsPage` initializes
- THEN `fe-async-content` displays products from `@repo/infra`
- AND `@repo/presenters` transforms domain models to view models

##### Scenario: Products fail to load
- GIVEN the API returns an error
- WHEN `ProductsPage` receives the error
- THEN `fe-async-content` displays error state
- AND no unhandled promise rejections occur

##### Scenario: Products loading state
- GIVEN the API is in-flight
- WHEN `ProductsPage` is rendering
- THEN `fe-loader` displays loading indicator
- AND no flash of empty content appears

#### Requirement: Angular ComponentsPage Showcase
The system SHOULD render a showcase of fe-* components demonstrating their usage.

##### Scenario: Components page renders all showcase components
- GIVEN the Angular app navigates to `/components`
- WHEN `ComponentsPage` loads
- THEN fe-button, fe-card, fe-icon, fe-rating examples render
- AND each example demonstrates correct property binding

#### Requirement: Angular Route Navigation
The system SHALL support hash-based routing matching Vue behavior.

##### Scenario: Navigate between pages
- GIVEN the Angular app is at `/`
- WHEN the user clicks "Components" in nav
- THEN the URL changes to `/components`
- AND `ComponentsPage` renders

##### Scenario: Direct URL access
- GIVEN the URL is `/#/components`
- WHEN the app loads
- THEN `ComponentsPage` renders directly
- AND no redirect occurs

#### Requirement: Angular AppShell Navigation
The system SHALL provide navigation shell with links to Products and Components.

##### Scenario: AppShell renders nav
- GIVEN the Angular app is bootstrapped
- WHEN the root component renders
- THEN AppShell displays navigation links
- AND active link is highlighted based on current route

### MODIFIED Requirements

#### Requirement: Angular metaMap Injection (MODIFIED from 4.3)
The system SHALL provide `META_MAP_INJECTION_KEY` as Angular `InjectionToken<MetaMap>`.

##### Scenario: Default metaMap provided at factory
- GIVEN no tenant override for metaMap
- WHEN the factory bootstraps
- THEN `META_MAP_INJECTION_KEY` provides default framework metadata
- AND components can inject it via `inject(META_MAP_INJECTION_KEY)`

##### Scenario: Tenant overrides metaMap
- GIVEN tenant provides custom metaMap
- WHEN the factory bootstraps with tenant config
- THEN `META_MAP_INJECTION_KEY` returns tenant's metadata
- AND default metadata is not accessible
