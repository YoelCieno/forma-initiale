## R11 — Angular major cadence (deep dive)

- **Cadence:** Angular majors every ~6 months (v22: 2026-06; v23 expected ~2026-12, will need TS 7). Semver-major churn is by design — upgrade is a supported, tooled path (`ng update`).
- **Coupling:** each major may bump required TS major (v22 needs TS ≥6.0 <6.1; v23 → TS 7). Root repo TS `^6.0.3` must be re-evaluated per upgrade; peer-pin drift in `@angular/build` is the forcing function.
- **Monorepo impact:** `bun overrides` (vite/vitest → vite-plus-*) and peer pins must be re-validated each `ng update`. Root overrides already flagged as risky for Angular's exact-pinned vite (R1).
- **Mitigations:**
  1. Keep white-label-angular deps **minor-pinned** (`~`) not floating (`^`).
  2. Schedule `ng update` deliberately in roadmap — no automatic/dependency-bot major bumps for the Angular app (renovate: restrict to minor/patch for white-label-angular).
  3. Upgrade together with the repo's TS/vite/vitest story; run R1 smoke (`ng build`/`ng serve`/`ng test`) after every major.
  4. Document each major bump in this register (append row per Angular version, with observed issues).
