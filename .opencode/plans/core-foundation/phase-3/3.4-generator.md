## Design Decisions (2026-06-30)

Agreed generator design from architecture discussion:

### Metadata

- Generator asks ONCE about metadata generation mode
- Scaffolds 2-3 placeholder entries in a `metadata.ts` file with commented examples
- Mode determines: fixture-based (static product map) vs real API integration pattern

### Tokens / Theming

- **Removed palette calculation** — WA theme system provides all derived brand colors
- 4 theme choices at gen time: `default` | `awesome` | `shoelace` | `custom`
- Predefined themes: import WA theme CSS, no tokens.css brand overrides needed
- Custom: validate hex → set single `--wa-color-brand-fill-normal` var, WA cascade handles rest
- `packages/generator/src/utils/palette.ts` reduced to `validateHex()` + `getThemeClass()` only (no HSL math)

- Prompt for 1 primary brand CSS variable (e.g. `--brand-hue` or a primary color hex)
- Generator calculates a palette with HSL values from the primary input
- Templates `src/styles/tokens.css` with calculated palette + commented placeholders for remaining brand vars
- Generated file includes `@wa-theme-default` class and `--wa-color-*` var overrides

### Component override

- OPTIONAL prompt: "Override a component? [y/N]"
- If yes: ask for component name, scaffold a stub in `src/components/<Name>.vue`
- Ensure `vite.config.ts` includes `componentDirs: ['./src/components']`
- Only component override — page override skipped in v1

### Page override

- **Skipped in v1** (pencilled for future phase)

### New routes

- **Skipped explicit scaffold in v1**
- Add a **COMMENTED example** in generated `main.ts` showing how to use `extendRoutes`

### Updated factory API (target state)

- `createWhiteLabelApp` now accepts `extendRoutes?: RouteRecordRaw[]` in addition to `routes`
- When `extendRoutes` is provided, WL default routes merge automatically — tenant doesn't repeat them
- Generated tenant `main.ts` uses `extendRoutes` (simpler pattern)
- `routes` kept as full override for advanced use (backwards compat)
- Generator assumes factory API has been updated before generator is built

## Unplanned Changes

Changes that occurred during execution not described in original plan:

- **Bootstrap layer extraction**: Factory code was split from a single `src/app.ts` into `src/bootstrap/app.ts` + `src/bootstrap/init.ts`. `createWhiteLabelApp()` in `app.ts` delegates to `useWhiteLabelApp()` from `init.ts` for MSW setup, shell resolution, route merging, and meta injection. This cleanly separates concerns and makes testing easier.

## Future factory improvements (pencilled)

Not scheduled for this phase — ideas recorded for future consideration:

- **Component/page override via Vite plugin resolution order**: Currently implicit and not factory-aware. If multiple tenants override the same component, resolution order is fragile. A future factory API could expose explicit override registration.
- **App shell override is all-or-nothing**: No slot-based layout extension from WL. Tenant must replace entire `App.vue` to change shell structure. Future: define layout regions (header, main, footer, sidebar) that WL shell exposes for tenant injection without full replacement.
- **No slot system for injecting content into WL layout regions**: Tenants cannot inject nav items, toolbar actions, or sidebar content into WL layouts without forking the shell. Future: a slot/region registry API.
- **CSS/token imports managed outside factory**: Tenants manually import `@repo/ui/styles`, theme, and tokens. Future: factory could auto-register theme dependency or accept a theme option.
- **Any other factory API improvements** discovered during tenant development or generator use.
