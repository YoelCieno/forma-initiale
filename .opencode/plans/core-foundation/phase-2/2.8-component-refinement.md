## Tasks

### 1. Convert fe-card from class-based WC to hybridJS `define()` pattern

**Why:** Consistency. fe-button, fe-icon, fe-rating use `define()` + `html` tagged literal + `shadow: true`. fe-card uses `class FeCard extends WaCard {}` — different pattern, no hybridJS.

**Approach (KISSME):**
- Replace class extends with hybridJS `define()` like fe-button
- Forward all WaCard props: `appearance`, `orientation`, `withFooter`, `withHeader`, `withMedia`
- Keep `shadow: true` for consistent rendering

**Step-by-step:**
1. Read WA Card agent skill for component API (props, slots, CSS parts)
2. Identify WaCard import path in `@awesome.me/webawesome/dist/components/card/card.js`
3. Rewrite `fe-card.ts` using `define()` + `html` with `shadow: true`
4. Forward all WaCard props through template
5. Update `FeCardElement` interface to match
6. Verify tests pass

### 2. Add `disabled` property to fe-card

**Why:** Users expect to disable cards in certain UI states (unavailable products, locked content, etc.)

**Approach (KISSME):**
- WaCard has no native `disabled` prop — this is purely CSS
- Add `disabled: boolean` to hybridJS definition, default `false`
- When `disabled=true`: CSS `opacity: 0.5; pointer-events: none;`
- Use `inert` attribute for accessibility (prevents focus)

**Implementation:**
```typescript
disabled: false,
render: {
  value: (host) => html`
    <wa-card
      appearance="${host.appearance}"
      orientation="${host.orientation}"
      with-footer="${host.withFooter}"
      with-header="${host.withHeader}"
      with-media="${host.withMedia}"
      ...inert="${host.disabled}"
      style="${host.disabled ? 'opacity:0.5;pointer-events:none;' : ''}"
    >
      <slot></slot>
    </wa-card>
  `,
  shadow: true,
}
```

**Accessibility:**
- `inert` attribute when disabled (Chrome 120+, FF 120+, Safari 17.5+)
- WA card currently has no `inert` — we add it for WC adherence

### 3. Create `<fe-async-content>` component

**Why:** Eliminate repeated `v-if`/`v-else` chains in Vue templates for async UI states (loading → error → data). Framework-agnostic WC can be used by any app.

**Approach (KISSME):**
- 3 states: loading → error → default
- Slots: `loading`, `error`, default
- No external deps beyond WA (uses `<wa-spinner>` as default loading indicator)
- Minimal API: `loading: boolean`, `error: string | undefined`

**Implementation:**
```typescript
import { define, html } from 'hybrids'

export interface FeAsyncContentElement extends HTMLElement {
  loading: boolean
  error: string | undefined
}

export const FeAsyncContent = define<FeAsyncContentElement>({
  tag: 'fe-async-content',
  loading: false,
  error: undefined,
  render: {
    value: (host) => {
      if (host.loading) {
        return html`
          <slot name="loading">
            <div class="fe-async-content__loading">
              <wa-spinner></wa-spinner>
              <span>Loading...</span>
            </div>
          </slot>
        `
      }
      if (host.error) {
        return html`
          <slot name="error">
            <div class="fe-async-content__error">${host.error}</div>
          </slot>
        `
      }
      return html`<slot></slot>`
    },
    shadow: true,
  },
})
```

**Vue usage:**
```vue
<fe-async-content :loading="loading" :error="error">
  <template #loading>Custom loading...</template>
  <template #error>{{ error }}</template>
  <div>Actual content here</div>
</fe-async-content>
```

**Test plan (unit via vitest in infra or web-vue):**
- Default state renders slotted content
- Loading state shows loading slot (or default spinner)
- Error state shows error slot (or error message)
- Toggle states (loading → error → data)

## Design Patterns Analysis

### KISSME (Keep It Simple, Most Efficient)
- fe-card disabled: CSS-only approach avoids JS overhead. No subclass, no complex logic.
- fe-async-content: 3 states via simple if chain. No state machine, no Vue reactivity coupling.
- fe-card hybridJS rewrite: Follows established pattern from 3 sibling components.

### SINE (Single Intent, No Exception)
- Each component has exactly one job:
  - fe-card: Display content in card container (with optional disabled visual state)
  - fe-async-content: Manage async UI state transitions
- fe-card disabled: Pure visual concern. No business logic mixing.

### POLA (Principle of Least Astonishment)
- `disabled` attribute on fe-card followed WA convention for other disabled components (fe-button)
- `fe-async-content` follows named-slot pattern familiar from Vue `<slot>` users
- hybridJS `define()` pattern matches existing fe-* components — developers know what to expect

### SoC+CQS (Separation of Concerns + Command-Query Separation)
- fe-card: Pure presentation, no data logic, no side effects
- fe-async-content: View-only state (loading/error), does not initiate data fetching
- Presenter layer handles data transformation; components only render

### CBD (Component-Based Design)
- fe-async-content replaces ad-hoc if/else chains with reusable component
- fe-card hybridJS → consistent with component family
- All fe-* components share same `define()` + `html` + `shadow` architecture
